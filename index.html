抓取下降与索引下降的关系

先发生9月22日索引集中重分类已索引减少 201.65 万，主体增量进入“已抓取未索引”。
后观察10月同期累计抓取减少Google 对 EN Product 的重复抓取和资源投入同步降低。
判断：两项数据共同指向 EN Product 页面池的质量和生命周期问题。由于 9 月 22 日索引下降早于 10 月同期抓取缩量，不能表述为“抓取下降导致索引下降”；更合理的解释是质量重评估先发生，抓取优先级下降是后续表现。

Root cause map

技术诊断：主因与放大器

把“索引下降”拆成四个可以被产研改造的系统问题。

主因 · P0

低 / 无搜索价值 URL 被集中重评估

证据：已抓取未索引增加 178.23 万；150 条三类样本近 180 天曝光与点击全部为 0；搜索曝光并未随索引量同步下跌；之后 EN Product 同期累计唯一抓取下降 47.4%。

解释力最强：Google 更像是在削减低价值索引库存，并降低后续抓取优先级，而非丢失有稳定流量的核心页。
放大器 · P0

URL 生命周期清退不完整

“已发现未索引”实时抽样 70% 已为 404/410，说明下架页仍可被 Sitemap、内链或其他入口持续发现。

为什么会消耗抓取与索引资源
Google 需要反复发现、调度和确认这些 URL，放大“已发现未索引”队列；失效页若仍在站内链接与 Sitemap 中，也会降低信号一致性。
风险 · P0

非等价商品 308 替换

重定向样本 20/20 为 308，多条目标与原商品语义明显不一致，如“陶瓷花瓶 → 姓名字母设计”“休闲 T 恤 → 篮球球衣”。

风险边界
这会稀释原 URL 信号，并可能被搜索引擎视为不相关重定向或软 404。这里只能确认语义不等价风险，不能声称 Google 已对这些 URL 作出某种具体处罚。
放大器 · P0

Product Sitemap 父索引处理异常

公网父索引现有 692 个有效子 Sitemap，每个约 1 万 URL；GSC 长期只识别 1 个子文件、10,000 个 URL。

对照 Goods 父索引：129 个当前子文件，GSC 读取 123 个，发现 6,136,482 个 URL。

同主机、目录、CDN 与 gzip/XML 形态下，差异更指向 Product 父索引历史快照、原子发布、缓存或版本一致性问题。
放大器 · P1

跟踪参数复制 URL

已抓取未索引中 16.5% 带参数；替代 canonical 池中高达 89.1%，主要是 f、linkPage、skuid。

虽然 canonical 可合并信号，但参数 URL 仍消耗发现、抓取与 canonical 计算资源。

数据边界

不能直接批量 noindex

GSC 零曝光 / 零点击不等于 GMV=0；BigQuery 数据止于 9 月 15 日，且缺少真实上线日期与交易字段。

生产规则必须 LEFT JOIN 商品主表与交易表，并设置白名单、观察期、版本和回滚机制。

Remediation roadmap

整改方案：先止损，再提质

每项动作都绑定判定规则、数据源、验收指标与回滚能力。

P0 · 生命周期

失效 URL 日清

  • 每日从商品主表提取停售/删除/失效状态。
  • 从 Product Sitemap、内链、hreflang、结构化数据中同步移除。
  • 无等价替代品返回 410；有一对一等价商品才允许 301/308。
  • 目标页必须一次到达 200、self-canonical、indexable。
验收：Sitemap 中 3xx/4xx/410 = 0；链式跳转 = 0
P0 · 重定向

停止非等价自动替换

  • 重定向匹配至少校验类目、核心属性、品牌/型号与意图。
  • 不满足语义等价时直接 410，不跳到“相似热销品”。
  • 对现存 308 建立抽样相关性评分与批量复核。
  • 保留规则版本、原目标、修复时间和回滚记录。
验收：抽样语义不等价率 < 5%
P0 · Sitemap

原子发布与端到端监控

  • 先生成并验证全部子文件，再以临时父文件原子 rename。
  • 更新 ETag / Last-Modified，发布后主动清理 CDN 缓存。
  • 比对预期子文件数、源站、边缘节点与 GSC 已读取数。
  • 禁止父索引短暂暴露只有 1 个子文件的中间态。
验收：692 个子文件可读；GSC 识别量持续恢复
P1 · 准入

Sitemap 只收高质量可索引页

  • HTTP 200、允许索引、自指 canonical。
  • 商品可售/有库存，标题、主图、价格和核心属性完整。
  • URL 无跟踪参数，无重定向与软 404 风险。
  • 状态变化后在 24 小时内退出 Sitemap。
数据：商品主表 + 页面渲染检查 + HTTP 探针
P1 · 参数

阻断参数 URL 的站内传播

  • Sitemap、内链、hreflang、schema 统一使用 clean URL。
  • 前端埋点用事件或属性，不把 f / linkPage / skuid 写入可抓取链接。
  • 保留 canonical 兜底，但不把它当作参数治理的唯一手段。
验收：新发现参数 URL 占比周环比持续下降
P2 · 分层

新品分层进入索引池

  • A：高潜商品进入高优 Sitemap，强内链。
  • B：质量合格但信号弱，进入观察池并补充内容。
  • C：信息不足/重复/不可售，暂不进 Sitemap。
  • 只有连接上线天数、曝光点击、GMV/订单后，才评估 noindex。
原则：零 GSC 活动不能单独触发 noindex

必须保留的判断边界

“零曝光/点击”不等于“零业务价值”
必须连接真实上线时间、GMV、订单、库存与利润等业务数据，再形成生产 noindex 候选。
GSC 原因变化不是逐 URL 迁移表
本报告按同日池子变化推断主要方向，不能证明某一条已索引 URL 必然进入了某个原因池。
Sitemap 异常是放大器，不是唯一根因
GSC 主体增量在“已抓取未索引”，说明大量 URL 已经被抓取；父索引读取异常会削弱发现与信号刷新，但不足以单独解释全部 201.65 万索引下降。
结论版本：2026-10-10
报告基于排查时点可见的 GSC、巡天、BigQuery、实时 HTTP 与 Sitemap 数据；所有线上改动需通过灰度、监控与回滚验证。
